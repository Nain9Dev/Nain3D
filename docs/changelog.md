# Changelog

## Unreleased — PDF report and share (spec 006, PR 3)

- A one-page A4 report is built in the browser (hand-written PDF writer, no dependencies): verdict and the limit that
  fails and by how much, profile, file name and size, SHA-256, UTC date, a capture of the model and the check table.
  Optional company and reference fields; the company is remembered on the device. It is shared through the system
  share sheet when the device supports files, otherwise downloaded. Spanish or English, following the interface.

## Unreleased — Store profiles (spec 006, PR 2)

- Users create, edit, duplicate and delete their own check profiles (up to 20) and pick one, or "automatic", for every
  review. Profiles live in `localStorage` on the device only; corrupt or invalid entries are skipped, never thrown.
  Field-by-field validation with the same bounds as the API, decimal commas accepted, keyboard operable native dialog,
  Spanish and English. Changing the active profile re-evaluates the model on screen.

## Unreleased — Store checks (spec 006, PR 1)

- Optional store checks, added only when a profile defines the limit: file weight, texture resolution, material
  budget, UVs and textures present (ADR-008, `Proposed`). The four built-in profiles are unchanged and still run
  four checks.
- Inventory reader in both engines (GLB JSON and PNG, JPEG and WebP headers; no image library) with parity tests on
  the bundled samples. The API accepts a custom profile as JSON (`custom_profile`); profile bounds are identical in
  Python and TypeScript and an out-of-range profile is refused. New rows are localised in Spanish and English.

## Unreleased — Hardening and project status

- API: uploads are limited to `.glb` (415), 50 MB (413) and checked for the binary glTF header (422) before
  parsing, as `SECURITY.md` already promised; unknown sample ids return 404 (the handler used a status constant
  that does not exist, so a failure would have been an unhandled error). Tests in `tests/test_upload_limits.py`.
- Client: Content-Security-Policy and referrer policy as meta tags; a Playwright test fails on any violation.
- Dependabot for npm, pip and GitHub Actions; `SECURITY.md` rewritten to match what is enforced and tested.
- `docs/project-status.md`: current state, paused items, how to resume, maintenance.

## Unreleased — Video export

- `npm run record:video`: renders the recording sequence offline, frame by frame with the manual clock, into an
  MP4 (vertical or horizontal, Spanish or English, any frame rate). Deterministic and free of dropped frames.

## Unreleased — Case study

- `docs/case-study.md`: the problem, the fail-closed rule, architecture, decisions with their ADRs, evidence and
  honest limits. Linked from the README and from the page footer (*Caso de estudio* / *Case study*); a test
  checks that every relative link resolves.

## Unreleased — Evaluate your own model

Specification: `specs/005-upload-own-model/`.

- Visitors can choose or drop their own `.glb` (up to 25 MB) and get the verdict in the browser. Wrong type,
  empty and oversized files are refused with a localised message; unreadable geometry gives `INCOMPLETE`.
- On the public site no request is ever sent to an API (`shouldUseBackend`: local development hosts only), and
  the page states that the file stays in the browser. `.gltf` with external files is no longer offered.

## Unreleased — Honest in-browser evaluator

- The static site's evaluator now reads watertightness (every edge shared by two faces) and degenerate faces (area at
  most 1e-12 m2) from the GLB triangle data instead of guessing from the triangle count, and returns `INCOMPLETE`
  for geometry it cannot decode. Tests compare it with the Python engine on the bundled samples. The sneaker is
  now reported as an open surface proposed as furniture, as the Python engine does.

## Unreleased — Visual redesign and recording mode

## 1.0.0 — 2026-10-14 — Nain3D Architecture Modernization

Governing decision: ADR-001 (`Approved`). Specification: `specs/001-modernization-and-showcase/`.

### Added

- **FastAPI Modular Backend** (`src/nain3d/`) on port `8104`:
  - `POST /api/v1/conformance/evaluate`: Multipart `.glb` model evaluation with geometric feature extraction, AI proposal, and fail-closed deterministic contract enforcement.
  - `GET /api/v1/conformance/profiles`: Contract profile registry (`Monitor`, `Mobiliario (Chair)`, `Pieza Industrial`, `Prop / Decorativo`).
  - `GET /api/v1/conformance/samples` & `/download`: Built-in synthetic 3D GLB generator for zero-external-dependency benchmarking.
  - `GET /health` & `GET /health/ready`: Liveness and readiness probes.
  - Interactive Scalar OpenAPI Reference mounted at `/docs`.
- **Reactive Vue 3 + TypeScript Client** (`Nain3D.Client/`) on port `5376`:
  - Interactive Google `<model-viewer>` viewport with 360-degree rotation, lighting, and drag-and-drop `.glb` upload.
  - Side-by-side presentation: *"La IA Propone"* (probabilistic classification) vs *"El Contrato Dispone"* (deterministic mathematical gate).
  - Built-in Synthetic Samples drawer for instant 1-click model testing.
  - Dark glassmorphic design system matching the `naindev.com` portfolio standard.
- Comprehensive `pytest` test suite covering domain schemas, contract evaluator fail-closed logic, and API endpoints (9/9 passed).
- Governance documents: `AGENTS.md`, `CLAUDE.md`, `SECURITY.md`, `.editorconfig`.

### Changed

- Unfroze repository from legacy archived status and established open-source reference branding as **Nain3D Gateway**.
- Replaced monolithic Streamlit script with decoupled REST API + Vue 3 architecture.
